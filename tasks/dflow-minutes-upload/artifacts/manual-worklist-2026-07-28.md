## 왜 지금 하는가 — 순서가 결과를 가른다

재편철 배치는 **또박또박 폴더 구조를 정답으로 보고** D'Flow를 맞춘다. 그러니 **또박또박이 먼저 정리돼 있어야** 한다.

- 폴더명이 안 맞으면 → 배치가 D'Flow에 **새 폴더를 만든다** (중복 폴더 2개)
- 회의 위치가 안 맞으면 → 사람이 D'Flow에서 정리한 걸 **되돌린다**

정본 §4-④가 못박은 처방이다: **D'Flow 위치가 정답이면 또박또박에서 폴더를 옮겨라.** D'Flow만 고치면 다음 재전송에 다시 덮인다.

## A. 폴더명 통일 — **재편철보다 반드시 먼저**

| | 또박또박 | D'Flow |
|---|---|---|
| 이름 | **`ERP/영업팀`** | **`ERP/영업`** |
| 소속 회의 | 2건 | 2건(#1·#2) |

같은 조직인데 이름이 다르다. 이대로 재편철하면 D'Flow에 `영업` **과** `영업팀`이 공존한다.

- [ ] **어느 이름을 정본으로 할지 결정** — D'Flow에 선호가 있는지 회신 대기 중(없으면 또박또박이 정한다)
- [ ] 또박또박에서 `ERP/영업팀` → 정본 이름으로 **개명**
- [ ] ⚠️ **D'Flow는 폴더 개명이 전파되지 않는다**(정본 §2-E ⑧). 개명 후 **재전송된 건만** 새 폴더로 간다 — 기존 2건은 재편철 배치로 옮겨야 한다

> 정본 이름을 `영업`으로 정하면 또박또박만 고치면 되고, `영업팀`으로 정하면 **D'Flow 쪽도 개명이 필요**하다. 전자가 싸다.

## D. 고아 레코드 `019f87db-c94d` — **삭제하지 않는다**

| | |
|---|---|
| D'Flow | `원재료_2026.07.15_11시00분` @ `MES/물류` |
| 또박또박 | `id 34` `원료팀 2026.07.08` — **소프트 삭제됨** |

경위: D'Flow에 수동 업로드된 회의록을 또박또박 `id 34`(전혀 다른 회의, 07/08 녹음 55분)가 **claim으로 잘못 가져갔고**, 이후 `id 34`가 삭제되며 D'Flow 쪽만 남았다.

- [ ] **D'Flow에서 지우지 않는다** — 본문은 원래 수동 업로드분이라 내용이 살아 있다
- [ ] **재편철 `items`에서만 제외** (목표 경로를 만들 원본이 없다)
- [ ] **선택지 — `id 34` 복원 여부 판단**
  삭제 금지 정책을 세웠으니 복원이 자연스럽다. 복원하면:
  - D'Flow #7이 고아가 아니게 되고 재편철 대상에 정상 편입된다
  - 단 **claim 오매칭은 그대로다** — `id 34`(원료팀 07/08)와 D'Flow `원재료 07/15`는 다른 회의다. 복원한다면 연결도 끊고 재매칭해야 한다

## 실행 순서

```
A 폴더명 통일  →  B 회의 4건 이동  →  C 판정  →  D 결정
                                                    ↓
                                        (D'Flow R1 배포 후)
                                          재편철 1회차 dry-run
                                                    ↓
                                             E 자유 루트 정리
                                                    ↓
                                        (R2 후) 2차 전송 전환
```

**A~D가 끝나면 재편철 dry-run이 거의 전건 `already_correct`로 나온다** — 사람이 다시 판정할 게 남지 않는다. 그게 목표다.
