### 요청 5의 「＋한 줄 확인 요청」이 실측으로 소멸한 경위

## 2. R1~R3 일정 — 물어야 할 질문이 바뀌었다

### 소스가 준 답

- **R1 날짜: 없다.** `dflow-decisions-final-2026-07-27.md§A-1` — *"R1은 검증 종료 즉시 배포(**날짜 미확정** — 확정되면 별도 통보)"*. R3·R4도 조건만 있고 날짜 없음
- **운영은 아직 R1 미배포** — 커밋이 아니라 응답으로 확정:
  - `GET /minutes?include_archived=true&per_page=200` → 200, `total=41`. **41건 전부 `archived`·`folder_id`·`folder_path` 키 0건**
  - `GET /minutes/meta` → 최상위 keys = `limits`/`projects`/`teams`. **`folders` 키 없음**, `limits`에 폴더 깊이·폴더명 길이 상한 없음
  - `origin/feat/minutes-folder-path`가 `main`에 아직 미머지(`git merge-base --is-ancestor` = NOT MERGED)인 것과 정합

### 스모크 환경 — "0건"이 유지된다. 이번엔 D'Flow 문서가 자인한다

이번 pull로 들어온 6커밋은 전부 `origin/main`의 **배포·운영 가드레일**이다(`.githooks/pre-push` 2단 관문 · `docs/runbook-rollback.md` · `scripts/smoke-prod.mjs` · 마이그레이션 원장). 관문이 생겼으니 스모크 문제가 풀렸는지 확인했더니:

- `scripts/smoke-prod.mjs`가 검사하는 것 = **로그인 페이지 마커 3개 + CSS 구조(바이트·규칙수·`@layer`·반응형 유틸)** 뿐. `POST /minutes`·`POST /minutes/folder`·`folder_path`·`include_archived` **전부 미커버**
- URL은 `SMOKE_URL`로 바꿀 수 있으나 **Supabase는 항상 프로덕션 공유**
- **D'Flow 백로그 문서 자신이** "전용 테스트 Postgres **미확보**"를 미충족 조건으로 등재하고, §9가 "**런타임 스모크 미실시**"를 명시

→ 새 관문은 **CSS·레이아웃 회귀 전용**이고 우리 연동과 무관하다. 항목 2의 전제("스모크 0건")는 우리 추측이 아니라 **상대 문서로 확인된 사실**이 됐다.

### 그래서 물을 것

~~"R1이 언제입니까"~~ → D'Flow도 답을 못 가진 질문이다.

**"전용 테스트 Postgres 확보 계획이 있습니까, 없이 R1을 낼 겁니까?"**

둘 중 어느 답이 와도 우리 다음 행동이 정해진다:
- 확보 후 낸다 → 우리는 R1까지 대기(코드는 이미 19/19 완료)
- 없이 낸다 → **첫 실경계 검증이 운영에서 벌어진다.** 우리 spec은 전부 stub이라 서비스↔D'Flow 경계가 한 번도 안 돌았다. 재편철 dry-run을 **APPLY 전에 반드시** 통과시키는 절차를 문서로 못박아야 한다

배포 승인자는 소스 어디에도 지정돼 있지 않다 — `runbook-rollback.md`·`CLAUDE.md` 모두 "개인 세션이 `main` 직행" 전제다. **승인자 부재 자체가 팀장에게 보고할 사항이다.**

   └── [또박또박] 2차 (W2·W3·W4·W5·W6·W7·W8·W19)  ⛔ 반드시 R2 이후
