# 세컨드 브레인 API — 요구사항 캡처 (2026-08-30, 사용자 원문 기반)

idea.md 56번(회의 간 지식 축적)의 구현 방향 확정판. **또박또박 안에 지식 기능을 쌓는 대신, 회의 내용을 API로 외부에 제공하고 Claude Code·Claude 앱·기타 LLM 에이전트가 스킬을 설치해 소비하는 구조.**

## 사용자가 명시한 요구사항

1. 또박또박이 회의 내용(전사·요약·회의록 등)을 **API로 제공**한다.
2. **PAT(Personal Access Token) 류의 인증 장치** 필수.
3. API를 바로 쓸 수 있는 **스크립트** 제공.
4. 그 스크립트를 포함해 **LLM이 작업할 수 있는 스킬(skill)** 제공.
   - Claude Code에서 스킬 설치 시 동작.
   - **Claude 앱(claude.ai)** 에서도 스킬 설치 시 동작.
   - **다른 LLM 에이전트**도 스킬 설치 시 동작 가능해야 함 (특정 벤더 종속 금지).
5. 권한: 회의 소유자, 협업자 + 추가 역할은 추천받기로 함 (아래 추천안 참조).
6. 구현은 **최대한 병렬로** 진행.

## 권한 모델 추천안 (오케스트레이터 제안 — 킥오프 때 확정)

기존 코드에 이미 있는 주체: owner, admin, collaborator(MeetingCollaborator/FolderCollaborator, 폴더는 하위 상속), shared 토글. 이 위에 아래를 얹는 방안.

| 역할 | 범위 | 비고 |
|---|---|---|
| 소유자(owner) | 자기 회의 전체 읽기/쓰기 | 기존 |
| 협업자(collaborator) | 협업 회의 읽기/편집 | 기존, 폴더 상속 포함 |
| 프로젝트 멤버(member) | 프로젝트 내 shared 회의 읽기 | 신규 후보 — 프로젝트 단위 조회에 필요 |
| 뷰어(viewer) | 지정 범위 읽기 전용 | 신규 후보 — 외부 에이전트 기본값으로 적합 |
| 관리자(admin) | 전체 | 기존 |

**PAT 설계 권고**: 토큰은 사용자에게 종속되되(사용자의 권한을 초과 불가), **스코프를 좁히는 방향으로만** 동작.
- 스코프 예: `meetings:read`, `transcripts:read`, `summaries:read`, `search:read`, (옵션) `meetings:write`
- 범위 제한: 프로젝트/폴더 단위로 한정 가능
- 만료일 필수 + 즉시 폐기(revoke) + 마지막 사용 시각 표시
- 사용 감사 로그(어떤 토큰이 어떤 회의를 읽었는지)
- 기밀 구간 절단(redact) 이후 데이터만 노출 — 절단 전 원본 접근 불가

## 설계 시 결정할 사항 (킥오프 안건)

- API 형태: REST(JSON) 단일안 vs REST + **MCP 서버** 병행안. "다른 LLM 에이전트 호환" 요구를 고려하면 REST가 기본, MCP는 후보.
- Claude 앱 스킬의 실행 방식: 앱 스킬은 네트워크 접근 제약이 있으므로, 스크립트 실행 가능한 환경(코드 실행)과 커넥터 방식 중 검토 필요.
- 검색 API에 기존 VectorIndex(하이브리드 검색) 노출 여부.
- 스킬 배포 형태: repo 내 `skills/` 폴더 + 설치 스크립트, 또는 zip 배포.

## 병렬 분해 초안 (킥오프 때 재검토)

1. **백엔드 A**: PAT 모델·발급 UI·인증 미들웨어·스코프 검사
2. **백엔드 B**: 읽기 API(회의 목록/상세/전사/요약/검색) + 권한 필터
3. **클라이언트**: CLI 스크립트(bash/python) — 인증·조회·검색·마크다운 덤프
4. **스킬**: SKILL.md + 스크립트 동봉(Claude Code용) / 범용 에이전트용 사용 설명(벤더 중립) / Claude 앱용 변형
5. **문서·E2E**: API 레퍼런스, 토큰 발급 가이드, 통합 테스트

1·2는 인터페이스 합의 후 병렬, 3·4는 API 스펙 확정 즉시 병렬. 구현은 전부 서브에이전트(코딩=sonnet), feature 브랜치 선행.
