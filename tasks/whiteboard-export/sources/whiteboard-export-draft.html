화이트보드는 Artifact 타입이 아니라 HTML 파일로 정의했습니다.

이 계정에서 확인되는 Artifact 타입은 Data, Design, Design System, Docs, Slides 다섯 가지이고 화이트보드는 없습니다. 그래서 어제 만든 표준관리 회의 보드와 같은 형태로, 파일 하나로 열리는 HTML을 만듭니다.

위험 요소

중간

지시문 복사는 회의록 전문을 클립보드에 담습니다.

사용자가 claude.ai에 붙여 넣으면 회의 내용이 그 사용자의 claude.ai 계정으로 넘어갑니다. 복사 완료 화면에 이 점을 한 줄로 알립니다. 기밀 구간으로 잘린 내용은 최종 요약에 없으므로 함께 나가지 않습니다.

중간

서버 모드를 켜면 모든 웹 사용자가 서버 PC의 계정 하나를 나눠 씁니다.

관리자 설정 설명에 그대로 적어 두고, 기본값은 지시문 복사로 둡니다. 실서버에 claude가 설치·로그인돼 있는지는 아직 확인하지 않았습니다.

중간

데스크톱 앱에서 찾은 claude가 로그인되지 않았을 수 있습니다.

실행 파일 존재만으로는 알 수 없으므로, 실패 출력을 분류해 "터미널에서 claude를 한 번 실행해 로그인해 주세요"처럼 해결 방법을 보여 줍니다.

낮음

회의록 문장이 지시처럼 읽혀 이상한 출력을 낼 수 있습니다.

앱·서버 경로는 JSON 검증과 escape, 외부 연결을 막는 CSP로 막습니다. 복사 경로는 사용자 본인 Claude가 만든 결과를 사용자가 직접 받으므로 앱 바깥의 일입니다.

남은 결정

  1. 앱·서버 경로의 생성 방식을 B안(Claude는 JSON, 모양은 템플릿)으로 확정할까요?A안(Claude가 HTML 전체 작성)은 2~4분이 걸리고 회의마다 모양이 달라집니다. 복사 경로는 어느 쪽이든 HTML을 직접 받습니다.
  2. 복사 지시문에 회의록 전문을 넣을까요, ddobak-meetings 스킬용 짧은 명령만 넣을까요?시안은 전문을 넣는 쪽입니다. 스킬 명령(#276 회의를 화이트보드로 정리해줘)은 짧고 회의 내용이 클립보드에 남지 않지만, 스킬과 API 토큰을 설치한 사람만 쓸 수 있습니다. 둘 다 버튼으로 둘 수도 있습니다.
  3. 서버 모드에 사용량 제한을 둘까요?예: 같은 요약이면 저장본을 재사용하고, 사용자당 하루 n회로 제한합니다.
