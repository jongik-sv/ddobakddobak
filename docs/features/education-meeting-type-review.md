# 회의 유형 "교육" 추가 + 온라인 교육 화면 보조 검토

작성일: 2026-07-24 / 상태: §1~3 구현 완료(`training` 유형 추가), §4 화면 보조는 미착수

## 0. 현재 구조 (사실 확인)

- 회의 유형 정의는 `config.yaml`의 `meeting_types` 1곳 (9종: general, team, standup, brainstorm, review, interview, workshop, one_on_one, lecture → training 추가 후 10종).
- 백엔드: `PromptTemplate.load_default_templates`가 `config.yaml`을 읽어 DEFAULT_TEMPLATES 구성. DB `prompt_templates` 테이블이 오버라이드.
- 프론트: `frontend/src/config.ts`의 `MEETING_TYPES`가 같은 `config.yaml`을 소스로 사용, `promptTemplateStore`가 API 응답으로 대체(fallback = 정적 목록).
- **meeting_type의 유일한 실질 소비처는 `sections_prompt_for()` → 요약 프롬프트의 섹션 구조**. 그 외에 필터·집계·권한 어디에도 분기 없음 (`meetings_controller`는 기본값 `"general"` 저장만).
- 관리자는 `PromptTemplateManager` UI로 커스텀 유형을 이미 자유롭게 추가 가능 (`is_default: false`).

→ 판단 기준은 단 하나: **"교육"이 기존 유형이 못 내는 회의록 섹션을 요구하는가.**

## 1. 교육 vs 강연 vs 워크숍

비교 대상은 강연만이 아니다. **워크숍이 더 가까운 이웃**이다 (이미 `학습 내용 / 실습 결과 / 핵심 Takeaway` 보유).

| | lecture(강연) | workshop(워크숍) | training(교육) 후보 |
|---|---|---|---|
| 목적 | 통찰·영감 전달 | 실습 산출물 | 역량 습득·재현 |
| 청중 | 수동 청취 | 능동 실습 | 학습자(평가 대상) |
| 회의록 소비자 | "무엇을 느꼈나" | "무엇을 만들었나" | "무엇을 할 수 있게 됐나" |
| 반복성 | 1회성 | 1회성 | 커리큘럼·차시 반복 |

**잔여(residue) 테스트** — 교육이 원할 섹션에서 강연·워크숍이 이미 내는 것을 지우면:

- ~~개요/주요 내용~~ (강연 보유), ~~실습 결과/Takeaway~~ (워크숍 보유)
- 남는 것: **학습 목표**, **커리큘럼·차시 구성**, **핵심 개념·용어 정리**, **이해도 확인/평가·퀴즈**, **과제·후속 학습**, (조직에 따라) **이수·출결 증빙**

잔여가 얇지 않다. 특히 `학습 목표 ↔ 달성 여부`와 `용어 정리`는 강연·워크숍 어느 템플릿도 만들지 않는다. → **교육 유형 추가 정당함.**

## 2. "교육에도 여러 가지" — 몇 개로 쪼개야 하나

주제 축(온보딩/직무/안전/제품/컴플라이언스)으로 나누면 **내용만 다르고 회의록 구조는 동일** → 템플릿 1개로 수렴. 유형을 늘려도 사용자만 고르기 어려워진다.

구조가 실제로 갈리는 축은 2개뿐:

1. **강의형 교육** → 새 `training` 1개로 커버 (목표·커리큘럼·개념·평가·과제)
2. **실습형 교육** → **이미 `workshop`**. 새로 만들 필요 없음
3. (조건부) **의무·컴플라이언스 교육** → `이수 여부 / 출결 / 서명·증빙 / 법정 필수항목`이 구조적으로 다름. 조직에 법정 의무교육 기록 니즈가 있을 때만 별도 유형, 없으면 `training`에 흡수

→ 권고: **built-in은 `training`(교육) 1개만 추가.** 컴플라이언스는 필요 시 관리자 커스텀 유형으로 먼저 검증 후 승격.

## 3. 제안 템플릿 (config.yaml 추가안)

```yaml
  - value: "training"
    label: "교육"
    sections_prompt: |
      2. **구조화**: 교육에 맞게 학습 중심으로 구성하세요:
         - ## 교육 개요 (강사, 과정명/차시, 대상, 학습 목표)
         - ## 참석자 (입력된 참석자 목록을 그대로 표시. 참석자 정보가 없으면 이 섹션을 생략)
         - ## 커리큘럼 (다룬 주제를 순서대로, 소제목 사용)
         - ## 핵심 개념 (새로 나온 용어·정의를 표로 정리)
         - ## 예제/실습 (강의 중 다룬 예제나 간단한 실습의 절차와 결과)
         - ## 질의응답 (수강생 질문과 강사 답변)
         - ## 과제 및 후속 학습 (과제, 참고자료, 다음 차시 예고를 표로 정리)
         - 절차·단계가 있으면 flowchart 다이어그램으로 시각화하세요.
```

`## 예제/실습`은 워크숍과 일부 겹치지만 의도된 것 — 강의형 교육도 예제 시연을 포함한다. 워크숍은 "참가자 산출물", 교육은 "강사 시연 절차"로 문구를 분리했다.

구현 시 확인할 것:
- `db/seeds.rb`는 `find_or_create_by!` → **기존 설치 DB에는 신규 default 유형이 자동 반영 안 됨**. 시드 재실행 경로 필요 (실서버 배포 절차에 포함).
- 프론트는 별도 수정 불필요 — **확인 완료**: `frontend/src/config.ts:3`이 `import configYaml from '../../config.yaml?raw'`로 레포 루트 `config.yaml`을 직접 읽고, 백엔드도 같은 파일(`Rails.root.join("..", "config.yaml")`)을 읽는다. 소스는 단일 파일.
- 유형 순서: `lecture` 뒤에 배치 (강연·교육 인접 노출).

## 4. 온라인 교육 화면 보조 (웹/동영상 플레이어)

### 현재 가능한 것 / 없는 것

- 있음: 시스템 오디오 캡처 (macOS = ScreenCaptureKit `SCStream`, Windows = WASAPI loopback), 타임스탬프 북마크(`meeting_bookmark`), 이미지 첨부(`meeting_attachment`, png/jpeg/webp 허용, 50MB), 링크 첨부(`kind: link`), 용어사전(`domain_file`).
- 없음: **비디오 프레임 소스 전무**(오디오 전용 스트림), **LLM 파이프라인은 텍스트 전용**(`llm_service`에 vision/image 경로 없음), OCR 없음.

### 옵션 사다리 (비용 오름차순)

| # | 기능 | 효과 | 비용 | 비고 |
|---|---|---|---|---|
| 1 | **URL/자료 링크 첨부 강화** — 온라인 강의 주소·차시 링크를 회의에 붙이고 요약 컨텍스트로 주입 | 중 | S | `kind: link` 이미 존재. 거의 공짜 |
| 2 | **수동 슬라이드 스냅샷** — 녹음 중 버튼 → 현재 화면/선택 창 1프레임 캡처 → 첨부 + 타임스탬프 마커 연결, 회의록에 이미지 삽입 | 상 | M | macOS는 기존 `SCStream`에 비디오 출력 추가(화면 기록 권한 이미 보유). Windows는 Windows.Graphics.Capture/DXGI 신규 |
| 3 | **화면 텍스트 추출(OCR)** → 요약 프롬프트에 "화면 컨텍스트"로 주입 | 최상 | M~L | 전문용어 전사 오탈자 보정에 특히 큼(용어사전과 시너지). 로컬 tesseract vs vision LLM 선택 필요 |
| 4 | **슬라이드 전환 자동 감지** — 프레임 해시/히스토그램 diff 임계 초과 시 자동 캡처 → 슬라이드 덱 자동 재구성 | 상 | M | dedupe·저장량 캡 필수 |
| 5 | **동영상 플레이어 타임코드 동기화** | 중 | L | 로컬 파일 재생이면 기존 `file_transcription_job`으로 파일 전사가 먼저. 화면 캡처보다 우선순위 낮음 |

**권고 순서: 1 → 2 → 3 → 4.** 2까지만 해도 "슬라이드 보면서 정리" 체감의 대부분을 얻는다. 3이 진짜 품질 레버(음성만으로는 못 얻는 화면 위 고유명사·코드·수식).

### 반드시 먼저 정리할 리스크

- **플랫폼 매트릭스**: 웹 브라우저는 `getDisplayMedia`로 쉬움 / 데스크톱 Tauri는 WKWebView·WebView2의 `getDisplayMedia` 지원이 불확실 → **네이티브 경로 전제로 잡고, 착수 전 실측 확인 필요** / Android(MediaProjection)는 후순위.
- **프라이버시**: 전체 화면 캡처는 민감정보 유출 경로. 창(window) 단위 선택 + 캡처 직후 미리보기·삭제 UI 필수. 캡처본은 서버 첨부로 저장됨 → 협업자 공유 범위와 충돌 검토.
- **저장량**: 자동 캡처는 용량 폭증. 프레임 해시 dedupe + JPEG 품질 제한 + 회의당 최대 장수 캡.
- **권한**: macOS 화면 기록 권한은 시스템 오디오 때문에 이미 요청 중 — 비디오 추가 시 사용자 인지 문구 갱신 필요.

## 5. 결론

1. `training`(교육) **1개만** built-in 추가. 워크숍이 실습형을 이미 커버하므로 교육 계열을 여럿 만들지 말 것.
2. 컴플라이언스/의무교육은 니즈 확인 후 — 우선 관리자 커스텀 유형으로 검증.
3. 화면 보조는 별도 기능 트랙. 링크 첨부 → 수동 스냅샷 → OCR 컨텍스트 주입 순. 착수 전 WebView `getDisplayMedia` 지원 실측 + 프라이버시 UX 결정 선행.
